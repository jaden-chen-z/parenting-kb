## 5. 三审教训沉淀(给后续 Phase)

### 5.1 Fallback 路径前置校验
任务书 fallback 列表的"英译版"前提要校对(Pikler `.md` 实际是德文原版,不是英译)。
**教训**:fallback 选择前先 head 文件确认语言。

### 5.2 G-XXX glossary 已被并行 session 创建
Write 时报"File has not been read yet" → Read 后发现已存在(并行 session 占位)。
**教训**:全部 glossary Write 前先 ls/Read 确认是否已存在,如已存在用 Edit。

### 5.3 YAML 块标量符号 `>` 触发 parse 错
列表项 `- > 120` → YAML 解析为块标量。
**教训**:列表项不能以 `>`、`|`、`!`、`*` 等保留符号开头。

### 5.4 段 ID 实时变化(并行 session 写)
启动时 max ID 跟终版差很大(并行 session 写 +200 buffer)。
**教训**:启动时 ls + 写完一批后再 ls 验证,新加卡用更高 ID 增量避撞。

### 5.5 Bowlby related 硬指标因 fallback 自然降级
任务书原"≥ 50% 卡含 Bowlby related",实际松田跟依恋理论关联弱,达到 23%。
**教训**:fallback 路径下,任务书源-specific 硬指标要主动调整,不能强求。

### 5.6 用户"不限数字"提示极有价值
原计划 35-42 张,用户提示 → 重审中国家长高频痛点 + 松田前卫立场 → 补 5 张高价值卡(自慰 / 反自体中毒 / 防过胖 等)。
**教训**:任务书数字目标是参考,内容定数才是真核心。
