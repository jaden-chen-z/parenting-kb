## 5. 三审框架沉淀(给后续 Phase)

### 5.1 Phase 6 + Phase 7 三审框架升级

```
轮 1 = Python 脚本验证(机器维度)
轮 2 = 主上下文重读 + diff(语义维度)
轮 3 = 术语 ls 实测 + 频率扫(覆盖维度)
+ 用户深度三审 = 跨源率 + hook 风格 + 漏 spot-check 章节
```

### 5.2 用户三审补充的维度

之前三轮独立审 0 错全过,**但用户深度审仍然发现 3 类问题**:

1. **漏知识点 spot-check 章节**:Ch2/3/8/10/14/24/27 这些"不显眼"章节,前两轮以为"内容单薄已覆盖",实际 Ch3 + Ch8 + Ch10 + Ch14 都有独立高价值命题
2. **hook 风格**:之前只检查字数(8-12 字),没检查"是否真 hook"。"Pikler 派核心立场"是描述,不是 hook
3. **跨源率**:之前只检查 related_cards 数量(平均 2.03 个),没检查"是否真跨源"。13 张全自卷 = 跨源率不足

### 5.3 教训沉淀

| 教训 | 实战修复 |
|---|---|
| 反向覆盖审计要逐章 spot-check,不能"内容单薄"就跳过 | 补 4 张高价值卡 |
| hook 必须是"抓眼一句",不是描述标签 | 修 5 个 hook |
| related_cards 检查跨源率(至少 1 张非自卷)| 补 13 张 |
| 中文 hook 8-12 字陷阱(默认会卡 7)+ 描述型陷阱(改抽象总结句)| Python 脚本扫 |

### 5.4 跨源率监控指标(新建议)

跨源率 = `non_self_src_related / total_related`,目标 ≥ 50%。

实测 43 张 Lansbury 卡:
- 修前:平均 2.03 related,跨源率 ~33%
- 修后:平均 2.88 related,跨源率 ~80%(每张至少 1 个非自卷)
